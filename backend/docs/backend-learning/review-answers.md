# 复习自测答案

先独立回答每章末尾的问题，再对照这里检查。能够结合当前代码说明原因，比只记住术语更重要。

## 第一章

1. 不一定。一个 Spring Boot 应用可以由多个 Maven 模块组成，也可以包含多个业务功能。独立启动、部署才是应用边界，模块只是代码与构建边界。

2. 是同一应用的三个运行实例，可能在不同机器上。它们可以共同处理请求，但不是因为数量增加就成为三个业务应用。

3. Java 是语言；Spring Boot 组织、配置和启动应用；Dubbo 提供 RPC 及相关服务治理能力；MySQL 管理持久化数据并执行 SQL。

## 第二章

1. 不会。URL 由映射注解、类级路径等配置决定，Java 方法名本身不决定对外地址。

2. 不是。Controller 是请求入口，底层连接、调度、参数转换和 JSON 编解码由 Web 框架及相应组件负责。

3. 模拟器通常可用 localhost 访问 Mac；真机的 localhost 指手机自身，需要使用 Mac 的可达地址。

## 第三章

1. ShopDAO 是长期协作依赖，在对象创建时提供；shopId 是每次请求的数据，通过方法参数传入，不能随意保存在共享字段。

2. 默认通常不是。Spring 单例组件可以被多个请求线程调用，线程安全要看是否修改共享状态。

3. 不会。record 提供数据对象的语法与访问方法；数据库持久化仍需 SQL、映射代码或 ORM 配置。

## 第四章

1. modules 把子目录纳入父工程构建；dependency 声明当前模块实际需要哪个组件。兄弟模块不会因为同属父工程就自动互相依赖。

2. API 的 POM 继承父配置。调用方解析依赖时也需要解析这份父 POM，所以第一次从父工程 install 更方便。

3. 不会。install 生成并安装本地构建产物；要启动服务仍需运行 main、Boot 插件或可执行 JAR。

## 第五章

1. Gateway Starter 已实现匹配和转发，路由配置把 /shop/** 指向店铺 HTTP 地址。POST 的方法、路径和请求体由框架转发。

2. 不会。默认会传回下游状态与响应，或在连接等失败时产生网关错误；错误转换需要明确配置或代码。

3. 不同。路由网关转发 HTTP；BFF 可聚合业务数据；注册中心帮助发现服务地址，不转发每次业务请求。

## 第六章

2. 不一定。调用方若仍按 desc 解码，需要调整模型或字段映射；具体未知字段处理取决于 JSON 配置。

3. 不能。请求可能已执行但响应丢失或返回太晚，写操作重试需考虑幂等性。

## 第七章

1. API JAR 只提供契约；Dubbo 依赖和配置负责服务暴露、代理创建、地址发现与网络通信。

2. 不够。调用方需要获得新 API JAR、更新返回类型等代码并重新构建运行；还要考虑老调用方兼容。

3. 不能。Dubbo 网络调用通常使用 RpcException 等 RPC 异常，RestClientException 属于 HTTP 客户端异常体系；业务异常另行约定。

## 第八章

1. 网关位于业务 HTTP 请求路径上并转发请求；注册中心向调用方提供地址信息，调用方再直接连接提供方。

2. 不说明。调用方可能有内存或磁盘缓存、已有连接；要结合注册数据、移除直连配置和地址变更实验判断。

3. 不一定。发行包包含程序和配置，dataDir 指向运行数据目录，可位于其他位置。

## 第九章

1. 关闭 DBeaver 只断开一个客户端，MySQL 可继续服务；关闭 MySQL 后所有客户端都无法正常发起新的数据库操作。

2. 不会。当前对象是内存中的查询结果，持久化更新必须执行 SQL。ORM 的托管实体行为也需要具体配置与事务，不能套用到普通 record。

3. 表定义了 AUTO_INCREMENT 和 DEFAULT CURRENT_TIMESTAMP，省略字段时由数据库填写。

## 第十章

1. id 是稳定用户标识；login_name 是登录账号且当前要求唯一；nickname 是展示昵称，可以重复。其他表引用用户时可命名为 owner_user_id 等。

2. 不应该。当前更新 SQL 不包含 created_at，传入的模型值不会覆盖数据库创建时间。

3. 在每条商品记录中保存 shop_id；DAO 用 WHERE shop_id = ? 进行数据库内筛选，而不是全量读入 Java。

## 第十一章

1. 不是。工作线程数量与连接数量是两类资源；部分线程可能等待空闲连接。

2. 不代表。DAO 没有共享请求状态，只说明对象层面可并发使用；过期的完整字段更新仍可能覆盖其他人的修改。

3. 数据库处理能力和锁竞争可能已经是瓶颈，增加连接会增加并发压力。应先分析查询、事务、锁等待和资源负载。

## 第十二章

1. Connection refused 通常发生在连接建立前，目标没有相应监听等；HTTP 404 说明已收到 HTTP 响应，但路由或资源未找到。

2. MySQL 正常提交的数据在持久化存储中；Java 正在运行的是已加载、编译的代码，当前未配热重载，修改源码需重新运行。

3. Maven 生命周期会运行测试，SpringBootTest 加载 Dubbo 可能绑定相同端口。构建失败摘要不等于正式应用的 main 在启动。
